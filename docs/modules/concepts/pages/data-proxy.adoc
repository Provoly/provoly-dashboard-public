= Accès aux données pertinentes on-time

== Problématique

Les quantités de données récupérées par l'application ont beaucoup grandi lors de l'ajout de réelles descriptions géographiques
( par exemple les coordonnées géographiques des régions avec une précision assez grande). Alors que ces données n'étaient pas
forcément utiles pour toutes les représentations (par exemple, une carte en a besoin, mais un graphique ou un tableau, non).

Il a donc été décidé d'exclure les données géographiques si elles n'étaient pas nécessaire. Cependant, il nous fallait un moyen d'éviter
de modifier l'ensemble de ces accès, et on ne voulait pas non plus ne pas permettre l'utilisation conjointe de données (car
actuellement, les widgets partagent leurs données), ni modifier les modèles.

== Solution

Afin d'arriver à réaliser cela, un paramètre excludeGeo peut-être ajouté aux requêtes afin d'ignorer ces attributs.
Celui-ci est déterminé en fonction de chaque type de widget, grâce à la propriété
(détails dans le chapitre "Comment faire pour limiter les appels à /items") autoLoadDatasource.
